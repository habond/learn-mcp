Testing Integration

Verify that your MCP server works correctly with Claude Desktop.

Verifying Server Connection

After configuring your server and restarting Claude Desktop, you should verify that the connection is working properly.

Check Server Status

Claude Desktop provides visual indicators for MCP server status. Look for the MCP tools icon in the input area:

text 
┌────────────────────────────────────────────────────────────┐
│  Claude Desktop                                             │
├────────────────────────────────────────────────────────────┤
│                                                             │
│  [Chat conversation area]                                   │
│                                                             │
├────────────────────────────────────────────────────────────┤
│  [Message input]                          [Tools icon: 🔧]  │
│                                                             │
│  Clicking the tools icon shows available MCP tools          │
└────────────────────────────────────────────────────────────┘

Status indicators:
  ✓ Tools icon visible = Server(s) connected
  ✗ No tools icon = No servers connected or configuration error

View Available Tools

Click the tools icon (or hammer icon) to see all available tools from your connected MCP servers:

text 
Available Tools:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
weather
├── get_weather
│   └── Get current weather for a city
└── get_forecast
    └── Get 5-day weather forecast

filesystem
├── read_file
│   └── Read contents of a file
├── write_file
│   └── Write content to a file
└── list_directory
    └── List files in a directory

Test with a Simple Query

Ask Claude something that requires using your tool. Claude will automatically decide when to use MCP tools:

text 
You: "What's the weather in San Francisco?"

[Claude thinks: This requires weather data. I have a 'get_weather'
tool from the 'weather' MCP server. Let me use it.]

Claude: I'll check the current weather for you.

[Tool call: get_weather]
[Arguments: {"city": "San Francisco"}]
[Result: "San Francisco: 18°C, Foggy"]

Claude: The current weather in San Francisco is 18°C (64°F)
with foggy conditions - classic San Francisco weather!

Test Multiple Tools

If your server provides multiple tools, test each one:

text 
# Tool 1: get_weather
You: "What's the weather in Tokyo?"

# Tool 2: get_forecast
You: "What's the 5-day forecast for London?"

# Tool 3: (if you have more tools)
You: "Compare the weather in Paris and Berlin"

Test Resources (If Available)

If your server exposes resources, Claude can read them when relevant:

text 
You: "What weather data sources are available?"

Claude: Let me check the available resources from the weather server.

[Resource read: weather://sources]

Claude: The weather server provides data from the following sources:
- OpenWeatherMap (primary)
- National Weather Service (US only)
- Environment Canada (Canada only)

Test Prompts (If Available)

If your server provides prompts, you can ask Claude to use them:

text 
You: "Use the weather report prompt for New York"

[Prompt: weather_report]
[Arguments: {"city": "New York"}]

Claude: [Generates formatted weather report based on prompt template]

Expected Behavior

Here's what successful integration looks like:

Scenario Expected Behavior
Claude Desktop starts Server process is launched, handshake completes
Query needs tool Claude automatically calls the appropriate tool
Tool succeeds Result incorporated into Claude's response
Tool fails Error message shown, Claude explains the issue
Claude Desktop closes Server process is terminated cleanly

Common Test Scenarios

Run through these scenarios to fully test your integration:

text 
Test Checklist:

□ Basic tool call
  "What's the weather in [city]?"

□ Tool with multiple parameters
  "Get the weather in Paris in Celsius"

□ Tool with optional parameters
  "What's the weather in Berlin?" (uses defaults)

□ Invalid input handling
  "What's the weather in XYZ123?" (should handle gracefully)

□ Multiple sequential calls
  "Weather in NYC, then London, then Tokyo"

□ Error recovery
  [Stop your server, try a query, restart, try again]

□ Long conversation with tools
  [Have a 10+ message conversation using tools]
Tool Visibility

Claude doesn't always show which tool it's using in the chat. This is by design for a natural conversation experience. However, you can ask "What tools did you use?" and Claude will explain.

Monitoring Tool Usage

Add logging to your server to monitor tool calls:

python 
import sys
import json
from datetime import datetime

def log(message: str):
    """Log to stderr (doesn't interfere with STDIO protocol)."""
    timestamp = datetime.now().isoformat()
    print(f"[{timestamp}] {message}", file=sys.stderr)

def handle_tool_call(name: str, arguments: dict):
    """Handle a tool call with logging."""
    log(f"Tool called: {name}")
    log(f"Arguments: {json.dumps(arguments)}")

    # Your tool implementation
    result = execute_tool(name, arguments)

    log(f"Result: {json.dumps(result)[:100]}...")
    return result

View logs by running your server manually in a terminal while Claude Desktop is also running (though they'll conflict - this is better for debugging specific issues).

Success Criteria

Your integration is working correctly when:

  • The tools icon appears in Claude Desktop
  • Your tools are listed when clicking the icon
  • Claude uses your tools when appropriate
  • Tool results are incorporated into responses
  • Errors are handled gracefully
  • The server stays running throughout the session
Congratulations!

If you've made it this far, you have successfully integrated your MCP server with Claude Desktop. Your custom tools are now available to Claude!
