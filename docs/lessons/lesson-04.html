MCP Lifecycle Overview

Understand the three phases of an MCP connection: Initialization, Operation, and Shutdown.

The Three Phases of MCP

Every MCP connection follows a strict lifecycle with three distinct phases. Understanding this lifecycle is essential before building a working MCP server.

├─────────────────────────────────────────────────────────────────┤

│  │  ─────────────────────────────────────────────────────── │   │

Phase 1: Initialization (The Handshake)

The initialization phase is the handshake between client and server. No other operations can happen until this completes successfully.

Step Direction Message
1 Client → Server initialize request
2 Server → Client initialize response
3 Client → Server notifications/initialized
Initialization is Required

A server MUST reject any requests (except initialize) until the handshake completes. Attempting to call tools/list before initialization will result in an error.

Phase 2: Operation

Once initialized, the client and server can exchange messages freely. This is where the real work happens:

  • Tool discovery — Client queries available tools
  • Tool execution — Client invokes tools with arguments
  • Resource access — Client reads available resources
  • Prompt retrieval — Client fetches prompt templates
json 
// Example: Client lists available tools
{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/list"
}

// Server responds with tool definitions
{
    "jsonrpc": "2.0",
    "id": 2,
    "result": {
        "tools": [
            {
                "name": "get_weather",
                "description": "Get current weather for a location",
                "inputSchema": {
                    "type": "object",
                    "properties": {
                        "city": {"type": "string"}
                    },
                    "required": ["city"]
                }
            }
        ]
    }
}

Phase 3: Shutdown

The shutdown phase occurs when either party terminates the connection:

  • Client closes the connection gracefully
  • Server process terminates
  • Network connection drops
  • Timeout occurs

For STDIO transport, shutdown typically means the server process exits. For HTTP/SSE transport, the client simply stops sending requests.

Why the Handshake Matters

The initialization handshake serves several critical purposes:

text 
1. VERSION NEGOTIATION
   Client: "I support protocol version 2024-11-05"
   Server: "I also support 2024-11-05, let's use that"

2. CAPABILITY DISCOVERY
   Client: "I can do sampling"
   Server: "I provide tools and resources"

3. IDENTITY EXCHANGE
   Client: "I am Claude Desktop v1.0.0"
   Server: "I am weather-server v2.1.0"
Building Trust

The handshake lets both parties know exactly what to expect from each other. A client won't try to call tools on a server that doesn't support them, and a server knows what features the client can handle.

State Machine View

Your MCP server should track its connection state:

python 
from enum import Enum

class ConnectionState(Enum):
    """MCP connection states."""
    DISCONNECTED = "disconnected"    # No connection
    INITIALIZING = "initializing"    # Received initialize, not yet confirmed
    READY = "ready"                  # Handshake complete, operational
    SHUTDOWN = "shutdown"            # Closing down

class MCPServer:
    def __init__(self):
        self.state = ConnectionState.DISCONNECTED

    def handle_initialize(self, params):
        """Handle initialize request."""
        if self.state != ConnectionState.DISCONNECTED:
            raise Exception("Already initialized")
