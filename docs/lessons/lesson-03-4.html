Notifications

Add notification support and message type detection.

What is a Notification?

A notification is a JSON-RPC message that doesn't expect a response. The key difference from a request is the absence of an ID field:

json 
// Request (has ID, expects response)
{"jsonrpc": "2.0", "id": 1, "method": "tools/list"}

// Notification (no ID, no response expected)
{"jsonrpc": "2.0", "method": "notifications/initialized"}
MCP Notifications

MCP uses notifications for events like notifications/initialized (client is ready), notifications/cancelled (cancel a request), and notifications/progress (progress updates).

def create_notification(method: str, params: dict | None = None) -> dict:
    """
    Create a JSON-RPC notification (no ID, no response expected).

    Args:
        method: The notification method name
        params: Optional parameters

    Returns:
        A properly formatted JSON-RPC notification
    """
    notification: dict[str, Any] = {
        "jsonrpc": "2.0",
        "method": method
    }

    if params is not None:
        notification["params"] = params

    return notification

Step 2: Add Message Type Detection

Add these helper functions after create_notification:

python jsonrpc.py - Add after create_notification 
def is_request(message: dict) -> bool:
    """Check if a message is a JSON-RPC request (has method AND id)."""
    return (
        message.get("jsonrpc") == "2.0"
        and "method" in message
        and "id" in message
    )


def is_notification(message: dict) -> bool:
    """Check if a message is a notification (has method, NO id)."""
    return (
        message.get("jsonrpc") == "2.0"
        and "method" in message
        and "id" not in message
    )


def is_response(message: dict) -> bool:
    """Check if a message is a response (has id and result/error, NO method)."""
    return (
        message.get("jsonrpc") == "2.0"
        and "id" in message
        and ("result" in message or "error" in message)
        and "method" not in message
    )


def get_message_type(message: dict) -> str:
    """
    Determine the type of a JSON-RPC message.

    Returns:
        One of: "request", "notification", "response", or "invalid"
    """
    if is_request(message):
        return "request"
    elif is_notification(message):
        return "notification"
    elif is_response(message):
        return "response"
    else:
        return "invalid"

        ("Success Response", success),

        print(f"\n{name}:")
        print(json.dumps(msg, indent=2))
        print(f"  -> Type: {get_message_type(msg)}")

    # Show the detection logic
    print("\n" + "=" * 60)
    print("Message Type Detection")
    print("=" * 60)

        {"jsonrpc": "2.0", "method": "test"},                     # notification
        {"jsonrpc": "2.0", "id": 1, "result": {}},               # response
        {"jsonrpc": "2.0", "id": 1, "error": {"code": -1}},      # error response

    for msg in test_cases:
        print(f"\n{json.dumps(msg)}")
        print(f"  -> is_request: {is_request(msg)}")
        print(f"  -> is_notification: {is_notification(msg)}")
        print(f"  -> is_response: {is_response(msg)}")
        print(f"  -> type: {get_message_type(msg)}")

Quick Reference: Message Types

Type Has ID? Has Method? Response?
Request Yes Yes Yes (wait for it)
Notification No Yes No (fire and forget)
Response Yes No Is the response
Never Respond to Notifications!

When your server receives a notification, process it silently. Never send a response — even if processing fails. The sender isn't waiting for one, and sending one could confuse clients.
